TL;DR

  • 식단표 이미지 → OCR → 구조화 → 임베딩 → 저장 → 질문 응답까지 전체 파이프라인이 동작한다 (직접 확인 완료).
  • 단위 테스트 43개 전부 통과 (uv run pytest tests/menu -q).
  • 샘플 데이터(3개 업체 × 5일치)를 시딩하고 4가지 예시 질문에 정상 답변을 받았다.
  • 커밋은 1단계(OCR 기본 구조)까지만 되어 있고, 2단계(파서·임베딩·저장·질문응답) 코드는 아직 커밋되지 않음.
  • README 문서화는 아직 하지 않음.

무엇이 만들어졌나

메뉴 질문에 답하는 파이프라인을 6개 모듈로 나눠 구현했다. 화살표 순서대로 실제 데이터가 흐른다.

식단표 이미지
data/menu/*.png → menu_ocr.py
OCR (Mock / Tesseract)1단계 커밋됨 → menu_parser.py
날짜·요일·메뉴 구조화 → menu_embedding.py

menu_repository.py
SQLite 저장·조건 조회 → menu_agent.py
query_menu() — 질문 분석 + 응답 조립 → 사용자 답변 + 원본 이미지 경로
모듈역할
config.py업체(대성/KT/KT샐러드) 정의, 데이터·DB 경로 등 공통 설정
menu_ocr.py이미지 → 텍스트. MockOCRProvider(테스트용)와 TesseractOCRProvider 둘 다 지원
menu_parser.pyOCR 원문을 업체/날짜/요일/식사종류/메뉴목록 구조로 정리
menu_embedding.py메뉴 텍스트를 해싱 트릭 TF 벡터(256차원)로 변환, JSON 파일 기반 벡터스토어에 저장·코사인 유사도 검색
menu_repository.py구조화된 식단을 SQLite(data/menu/menu.db)에 저장, 업체/날짜 조건 조회, upsert로 중복 방지
menu_agent.py질문에서 업체·날짜·요일 추출 → 조건검색 우선, 필요시 벡터검색 보조 → query_menu() 최종 응답 반환
seed_sample_data.py샘플 이미지 3종을 실제로 OCR→저장까지 실행해 DB/벡터스토어를 채우는 스크립트

임베딩·벡터DB 선택에 대한 참고

Pinecone·sentence-transformers 같은 외부 모델/유료 서비스 대신, 해싱 트릭 기반 단어빈도 벡터 + 직접 구현한 JSON 벡터스토어를 사용했다. 인터넷 연결이나 모델 다운로드가 필요 없고 결정적으로 동작하지만, 실제 "의미" 이해가 아니라 "단어 겹침" 수준의 유사도라는 한계가 있다 (코드 내 주석으로 명시됨). 나중에 필요하면 VectorStore 클래스만 chromadb 등으로 교체 가능하게 설계되어 있다.

어떻게 동작하나 — 예시 시나리오

샘플 데이터를 시딩(uv run python -m app.menu.seed_sample_data)한 뒤 아래 4가지 질문을 실제로 넣어 확인했다.

Q. 오늘 KT 메뉴 뭐야?
A. 오늘 KT 점심 메뉴는 제육볶음, 미역국, 배추김치입니다. (업체+날짜 정확 → 조건검색)
Q. 내일 대성학원 점심 알려줘
A. 내일 대성학원 점심 메뉴는 김치볶음밥, 계란후라이, 단무지입니다.
Q. KT 샐러드 메뉴 알려줘
A. 업체만 지정되어 등록된 여러 날짜의 메뉴를 나열해 응답 (2026-07-20 월요일부터 순서대로)
Q. 이번 주에 돈가스 나오는 날이 언제야?
A. 2026-07-22 대성학원 점심 메뉴는 돈가스, 스프, 양배추샐러드입니다. (업체/날짜 미지정 → 의미검색으로 매칭)
